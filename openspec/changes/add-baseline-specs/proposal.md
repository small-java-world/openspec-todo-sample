# Baseline Specifications Proposal

## Why

既存の TODO アプリケーションには DESIGN.md が存在するものの、OpenSpec 形式でまとめられた仕様書はありません。今後の変更管理を円滑化し、AI アシスタントが仕様を参照しながら開発を支援できるようにするため、既存機能の仕様を OpenSpec 構造で整備する必要があります。

## What Changes

- **user-auth** capability の仕様を新規作成  
  - ユーザー登録・ログインの基本要件  
  - パスワードセキュリティと JWT 認証を専用要件に切り出し、各シナリオは JWT 要件を参照する形に整理  
  - 認証済みユーザー情報取得の期待値を明示

- **todo-management** capability の仕様を新規作成  
  - TODO の作成 / 一覧取得 / 個別取得 / 更新 / 削除 / 完了ステータス管理  
  - 所有者チェックやクロスユーザー制御を「User Data Isolation」要件に集約し、各 CRUD 要件から参照する構成に統一

- 既存の DESIGN.md / README.md の内容を OpenSpec の要件・シナリオ表現へ反映し、重複や不整合を解消

## Impact

- 対象仕様: `user-auth`, `todo-management`（新規作成）
- コード影響: なし（既存機能の仕様化のみでコード変更は伴わない）
- 期待効果:
  - 既存機能の真実の記録と将来の変更提案との比較が容易になる
  - AI アシスタントが仕様を参照しながら安全に実装を支援できる
  - 横断的な制約を要件単位で参照できるため、変更時の影響範囲を素早く把握できる
